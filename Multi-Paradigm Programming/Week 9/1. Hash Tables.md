# What is a hash table?
A **Hash Table** is a data structure that implements an **associative array**, which is a map from **keys** to **values**.

They are a powerful alternative to arrays and linked lists because they offer a combination of **efficient lookup, insert, and delete** operations.
- **Sorted array:** fast lookup (binary search), but slow inserts/deletes due to data sharing.
- **Linked list:** fast insert/delete, but slow lookup (must scan from the start, $O(N)$ time).

## Core components
A hash table is a **fixed-size** array. Its key components are:
- **Hash function:`h(k)`:** a function that maps a key `k` (which can be any type) to an integer index in the array. This index is called a "bucket" or "slot".
- **Deterministic:** a good hash function must be **deterministic** (the same key always maps to the same index) and **fast**.
- **Collisions:** a collision occurs when a hash function maps two different keys to the **same index**.
A **good hash function** minimises collisions by distributing keys **uniformly** across the table indexes.

## Hash function examples
- **Modular hashing (for integers):** `h(k) = h k mod |T|` where `|T|` is the table size.
	- **Pitfall:** a poor choice of table size can cause clustering. For example, hashing even numbers into a table of size 10 will only use the even-numbered slots. Using a prime table size (e.g., 11) provides better distribution.
- **String hashing:**
	- **Bad idea 1 (summing):** `h(S) = (S[0] + S[1] + ...) mod |T|`. This fails because **anagrams** (like "cat" and "act") will collide.
### A. sum of ASCII values (native approach)
- **Logic:** add up the string's ASCII values modulo the table size.
- **Code:**
```cpp
int hash_ascii_sum(string key, int table_size) {
	int sum = 0;
	//loop through string length N
	for (int i = 0; i < key.length(); i++) {
		sum += (int)key[i]; //add the ascii value.
	}
	return sum % table_size;
}
```
-  **Bad idea 2 (prefix):** hashing only the first 3 characters. This is faster but causes keys with the same prefix (e.g., "actor", "action") to cluster.
- **Better idea (polynomial):** compute $S[N-1]+S[N-2]*p+...+S[0]*p^{N-1} mod |T|$, using a prime number `p` (e.g., 31).
```cpp
#include <cmath>
#include <string>
using namespace std;

int hash_polynomial(string key, int table_size) {
	int hash_val = 0;
	int p = 31; //prime number choice.
	int n = key.length();
	
	for (int i = 0; i < n; i++) {
		//S[i] * p^(N-1-i)
		//Note: in real code, handle overflow or use horner's method
		hash_val += key[i] * pow(p, n - 1 - i);
	}
	
	return hash_val % table_size;
}
```

# Collision handling strategy 1: chaining
This is the most common strategy. When a collision occurs, the colliding elements are stored in a **linked list** at that index.
- **Structure:** the hash table array is an array of pointers to the heads of linked lists.
```cpp
#include "intlist.h" //using the class from the pointers pdf

class ChainedHashTable {
	private:
		int M; //size of the table
		Intlist* table; //array of Linked Lists
	public:
		//constructor: create an array of empty lists
		ChainedHashTable(int size) {
			M = size;
			table = new Intlist[M]; //dynamic allocation of array
		}
		
		//destructor
		~ChainedHashTable() {
			delete[] table; //the intlist destructor cleans up nodes.
		}
		
		//insert function below...
}
```
- **Implementation:** in C++, each list node contains the data (key and value) and a `Node* Next` pointer to the next item. The end of the chain is marked by `nullptr`.
```cpp
void Insert(int key) {
	//1. compute index
	int index = key % M; //simple modular hash
	//2. insert into the specific linked list at that index using the 'Insert' method from the Intlist class
	table[index].Insert(key);
}
```
- **Performance:**
	- **Load factor ($λ$):** $λ = N|M$ (Number of keys / Number of slots).
	- **Worst case:** a bad hash function maps all $N$ keys to one slot, degrading performance to that of a single linked list. Lookup is $O(N)$.
	- **Average case:** with a good hash function, the average list length is $λ$. The cost of lookup is $O(1+λ)$ (1 to hash, $λ$ to search the list). If the number of keys is kept proportional to the table size (e.g., $λ≈1$), the cost is $O(1)$.

# Collision handling strategy 2: open addressing
In this strategy, all elements are stored **inside the array itself**. When a collision occurs, the algorithm **probes** for a different, empty slot according to a fixed sequence.
- **Advantages:** no pointers, no extra memory allocation for list nodes.
- **Disadvantages:** slower insertion (must find an empty slot), and performance degrades rapidly as the table fills up.

## Probing methods
- 1. Linear probing: if a slot is occupied, just try the next one in the table.
	- **Sequence:** $h(k),h(k)+1,h(k)+2,...(mod|T|)$.
	- **Disadvantage:** causes **clustering**, where keys bunch up in one part of the table.
```cpp
//assuming table is an array of integers initialised to -1 (empty)
void InsertLinear(int key, int table[], int M) {
	int index = key % M; //initial hash
	int i = 0;
	
	//loop while slot is occupied (collision)
	while (table[(index + i) % M] != -1) {
		i++; //move to next slow (step size = 1)
		
		//safety check: if table is full, stop to avoid infinite loop.
		if (i == M) return;
	}
	
	//found empty slot
	table[(index + 1) % M] = key;
}
```
- 2. Quadratic probing: probes "jump" further away to avoid clustering.
	- **Sequence:** $h(k),h(k)+1^2,h(k)+2^2,h(k)+3^2,...(mod|T|)$.
	- **Disadvantage:** can still cause "secondary" clustering and may fail to find an empty slow if the table is more than half-empty.
- **3. Double hashing:** uses a **second hash function** $h'(k)$ to determine the probe step size. $h'(k)$ must never return 0.
	- **Sequence:** $h(k),h(k)+h'(k),h(k)+2h'(k),...(mod|T|)$.
	- **Advantage:** this is the most effective method. Keys that collide at $h(k)$ will have different probe sequences (unless $h'(k)$ *also* collides), minimising clustering.

# Deletion and rehashing
## Deletion in open addressing
- **The problem:** you cannot simply delete an element from its slot. This would break the probe sequence for other keys.
	- *Example:* if 14 is at `h(14)=4` and 24 is at `h(24)=5` (due to collision), deleting 14 and leaving slot 4 empty would make a `search(24)` fail, as it would stop at the empty slot 4.
- **Solution: lazy deletion:**
	- Mark the slot as **"deleted"** (e.g., with a 'D' flag) instead of "empty".
	- **Search** operations must continue probing past "deleted" slots.
	- **Insert** operations can reuse the first "deleted" slot they find.

## Performance and rehashing
- **Load factor ($λ=N/M$):** for open addressing, $λ$ **must** be < 1.
- **Performance:** performance degrades *dramatically* as $λ$ approaches 1.
	- The average number of look-ups is $1/(1-λ)$.
	- At $λ = 0.5$ (50% full): 2 look-ups.
	- At $λ = 0.9 (90% full): 10 look-ups.
- **Rehashing:** to maintain good performance, the table must be resized when the load factor gets too high (e.g., $λ > 0.5$).
- **Process:**
	1. Create a **new, larger table** (e.g., double the size).
	2. You **must re-hash** every key from the old table using the **new table size** and insert them into the new table. You cannot simply copy the old table.
```cpp
void rehash() {
	int oldSize = M;
	int newSize = M * 2;
	int* newTable = new int[newSize]; //create T'
	
	//iterate through old table
	for (int i = 0; i < oldSize; i++) {
		if (table[i] != EMPTY) {
			//RE-HASH using new size
			int newIndex = table[i] % newSize;
			
			//... (perform linear probing insertion into new table)
		}
	}
	//...(delete old table, update pointer)
}
```
- **Gradual rehashing:** to avoid a long pause in real-time systems, both tables can be maintained. New writes go to the new table. Look-ups check the new table, then the old. Items are moved from the old to the new during idle time or on-the-fly when looked up.
