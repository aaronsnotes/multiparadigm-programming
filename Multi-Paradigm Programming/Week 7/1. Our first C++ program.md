This section covers the basics of C++, its advantages over C, and the fundamental structure of a "Hello World" program.

---
# Why C++?
- **Expressive:** allows you to express ideas from many application areas.
- **Widely used:** especially in engineering
- **Standardised:** defined by an ISO standard that is universally accepted.
- **Portable:** available on almost all computer types.
- **Use in:** Mars rovers, animation, graphics (Photoshop), GUIs, OSs, compilers, and chip design.

---
# C vs. C++
- **Compatibility:** C is *almost* a subset of C++. Most C code works in C++, but C++ has stricter type checking.
- **Exception example:** in C, `sizeof('a')` is 4 (size of an `int`), while in C++ it is 1 (size of a `char`).
- **Link compatibility:** you can link C and C++ program fragments together.

---
# Key C++ features (missing in C)
- **Object-oriented:** classes, member functions, derived functions, virtual functions.
- **Generic programming:** templates (C uses macros).
- **Error handling:** exceptions (C uses error-codes).
- **Function overloading:** using the same function name for different parameter types (C requires separate names).
- **Call-by-reference:** a simpler way to pass variables by reference (C requires pointers).
- **Memory management:** `new` and `delete` operators (C uses `malloc`/`free`).

---
# "Hello World" program
A comparison of the simplest C and C++ programs.

## C version:
```C
#include <stdio.h>

int main() {
	printf("Hello World!");
	return 0;
}
```
---
## C++ version:
```cpp
#include <iostream>
using namespace std;

int main() {
	cout << "Hello World" << endl;
	return 0;
}
```
---
## Compiling C++
- **Command:** `g++ example.cpp`
- **Strict flags:** your code will likely be compiled with flags that enforce modern standards and warn about potential issues: `g++ -std=c++17 -Wall -Wextra -pedantic`.

---
# Anatomy of the C++ program
- `#include <iostream>`: this is a **header** file for the I/O Stream library. C++ Standard Library headers do not end in `.h`.
- `using namespace std;`: this tells the compiler to use the **namespace** named `std` (standard). This avoids having to write `std::cout` and `std::endl`.
- `int main() { ... }`: the **main function**, which is the entry and exit point for every C++ program. Returning 0 is optional but encouraged.
- `cout << "Hello" << endl;`: this is a statement.
	- `cout` stands for "character out".
	- `<<` is the output stream operator.
	- `endl` inserts a new line and flushes the output buffer.
	- Strings must use **double quotes** `"..."`.

---
# I/O
`cout` (Output) -- you can chain the `<<` operator to output multiple items.
```cpp
#include <iostream>
using namespace std;

int main() {
	int age = 38;
	cout << "Hello" << endl << "I am " << age << " years old\n";
	return 0;
}
```

#### Output:
```
Hello
I am 38 years old
```

`cin` (Input) -- `cin` is used for character input.
```cpp
#include <iostream>
using namespace std;

int main() {
	char input;
	cout << "Enter a character: ";
	cin >> input;
	cout << "You entered: " << input << endl;
}
```

#### Output (if user types 'a'):
```
Enter a character: a
You entered: a
```

#### Output (if user types '123'):
```
Enter a character: 123
You entered: 1
```
(It only reads one `char`.)

# Namespaces
Namespaces provide a scope for identifiers (variables, functions, etc.) to avoid naming conflicts.

## Example: custom namespace
```cpp
#include <iostream>
using namespace std;

namespace other {
	int x = 24;
}

int main() {
	int x = 48;
	//use the scope resolution operator :: to access x from 'other'
	cout << "other::x = " << other::x << endl;
	cout << "x = " << x << endl;
}
```

#### Output:
```
other::x = 24
x = 48
```

## Example: namespace conflict
You cannot `use` two namespaces that contain the same identifier.
```cpp
#include <iostream>
using namespace stf;

namespace other { int x = 24; }
namespace mine { int x = 48; }

using namespace other;
using namespace mine;

int main() {
	//AMBIGUOUS: does 'x' come from 'other' or 'mine'?
	cout << "x = " << x << endl;
}
```
This will produce a **compiler error:** `reference to 'x' is ambiguous`.
